## Performance investigation, not a competitive benchmark

Five standalone package starts before lazy initialization measured median internal first paint
269 ms and working set 100,966,400 bytes. A diagnostic run attributed 172 of 193 ms UI construction
to eager inspectors. Lazy factories reduced UI construction to roughly 19–22 ms, and initial widget
count from 257 to 114. The same five-run smoke method then reported:

| Metric | Recorded result |
|---|---:|
| Internal first-paint median | 87 ms |
| Internal workspace-ready median | 102 ms |
| Current-process working-set median | 98,336,768 bytes (~93.8 MiB) |
| Current-process private-memory median | 40,218,624 bytes (~38.4 MiB) |
| Standalone native package payload | 32,533,573 bytes (excluding manifest) |

Both runs use fresh isolated empty workspaces, a 1500x940 native window, the installed Windows
platform/fonts, and no active model/browser/terminal process. Timers begin inside main(), not before
OS loading. Memory is sampled by the smoke path after its screenshot. No CLI comparison, p95/p99,
real workload soak or guarantee of no slowdowns is established. Memory remains above the original
bare preview; further rendering/cache and multi-resource profiling is required, not hidden.

samples.json, ux-profile-ez47cwuh/smoke/native-smoke.json. Deployment manifests validate runtime
hashes and absence of Node/Electron/WebEngine. Packages are local unsigned development previews.
